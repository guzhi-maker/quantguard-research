# 三人小组协作方案

## 项目目标

把一个 A 股量化研究项目拆成可并行、可复核、可展示的三段工作：

```text
公开数据与智能体 -> 数据治理与实验叙事 -> 机器学习、组合风控与研究结论
```

最终交付包括：可运行应用、真实数据底稿、机器学习实验、组合风控、研究报告、PPT 和现场答辩。

## 角色与交付物

### 成员 A：数据获取与智能体

负责把“找数据”做成可重复运行的工程流程，而不是手工下载几张表。

- 维护数据源注册表：来源、字段、频率、限制、更新时间和使用条件。
- 实现公开行情连接器、重试与多源回退，保存原始快照和数据清单。
- 接入 DeepSeek，用工具调用完成“查数据源 -> 调接口 -> 校验字段 -> 写出清单”的任务。
- 记录每次智能体运行的提示词、工具调用、返回摘要和失败原因，不保存 API Key。
- 提供固定股票池、日期范围、复权方式和成交额口径。
- 生成覆盖度审计与 Parquet/DuckDB 研究派生层，保留原始 CSV 作为唯一证据。
- 编写数据采集测试和最小复现命令。

验收标准：

- 新成员执行一条命令即可拉取同一股票池和日期范围的数据。
- 派生层可从原始快照重建，行数与 manifest 一致，并能通过 DuckDB 或 Parquet 直接读取。
- 每条原始记录都能追溯到来源和抓取时间。
- 接口失败时不会静默使用演示数据。
- DeepSeek 只规划和调用工具，不直接编造价格、收益或风险数值。

### 成员 B：数据治理与科研表达

负责把原始数据变成“可解释、可审计、可展示”的研究资产，并主导 PPT。

- 检查日期、代码、复权、重复记录、缺失值、异常价格和短历史股票。
- 编写数据字典、缺失率表、行业分布、样本时间和数据血缘说明。
- 完成探索性分析：收益分布、波动、成交额、相关性和关键特征概览。
- 维护数据底稿编号，确认 A 交给 C 的版本没有被隐式修改。
- 主导 PPT 结构和课堂演示脚本，准备数据部分的答辩题库。
- 在每次模型更新后同步图表、口径和结论，检查“图与文字是否一致”。

验收标准：

- 能解释每个字段、清洗规则、样本筛选和已知偏差。
- 任一图表都能追溯到实验 ID、数据底稿 ID 和生成脚本。
- PPT 中的数据、模型、风控结论与页面一致。
- 能回答数据缺失、幸存者偏差、标签重叠、成交额估算等问题。

### 成员 C：机器学习、组合风控与研究结论

负责从治理后的数据得到可验证的模型和组合结果。

- 定义特征、标签、训练/验证/留出期和时间滚动方案。
- 比较基线、Ridge、随机森林、梯度提升等模型。
- 报告 Rank IC、R²、Top-20% 捕获、净超额、换手和最大回撤。
- 完成整手约束、交易成本、冲击成本、行业暴露和容量分析。
- 给出目标组合、风险行动和研究报告。
- 明确展示失败结果，不把验证期改善写成样本外有效。

验收标准：

- 特征只使用信号日及之前的信息，标签未来窗口未结束前不进入训练。
- 留出期不参与调参。
- 所有收益结论都同时说明基准、成本、样本期和不确定性。
- 研究报告可以由实验 JSON 和完整数据底稿复核。

## 交接接口

### A 交给 B

```text
data/raw/<run_id>/                  # 大文件，不进 Git
data/manifests/<run_id>.json       # 来源、日期、字段、行数、哈希，进 Git
```

原始数据必须只追加，不覆盖。修正数据时创建新的 `run_id`。

### B 交给 C

```text
data/curated/<dataset_id>/         # 治理后的数据，大文件不进 Git
data/manifests/<dataset_id>.json   # 数据契约、清洗规则和质量的机器可读清单
docs/data-dictionary.md
docs/data-audit.md
```

C 不应直接读取未经过 B 校验的原始文件。若发现数据问题，记录问题并交给 A 重新抓取或交给 B 修订，不能静默修补。

### C 交给全组

```text
experiments/<experiment_id>.json
reports/research/<experiment_id>.md
reports/exhibits/<experiment_id>/
```

B 用这些产物制作 PPT，A 检查数据来源与运行日志，三人共同审阅结论。

## 统一数据契约

原始行情至少包含：

```text
date, symbol, name, industry, open, high, low, close,
volume, amount, source, fetched_at
```

治理后的行情面板还必须包含：

```text
dataset_id, market_as_of, adjustment, row_count, symbol_count,
missing_pct, duplicate_count, quality_status
```

建模样本必须包含：

```text
date, symbol, features..., future_excess, label_end_date
```

约束：

- `future_excess` 和 `label_end_date` 只能用于目标与评估，不能进入特征。
- 训练样本必须满足标签结束日不晚于训练边界。
- 金额单位、成交量单位、复权方式和百分比口径必须写清。
- 成交额如果由 `volume * close` 估算，界面和报告必须标注“成交额估算”。

## GitHub 协作规则

建议使用以下分支：

```text
main
feat/data-agent
feat/data-curation
feat/model-risk
docs/slides
fix/<short-description>
```

工作规则：

- 每个人在自己的功能分支完成一个明确任务，再提交 Pull Request。
- 一个 PR 只解决一个角色范围内的问题；公共文件由当次负责人修改。
- 公共接口变化必须同步更新 `docs/data-contract.md` 和测试。
- 不提交 `.env`、API Key、原始大 CSV、模型缓存、临时日志或 `exports/`。
- 大数据通过 GitHub Release、网盘或可重复下载脚本共享，仓库只保留清单和质量报告。
- 每周至少做一次三方联调：A 能重拉数据，B 能重建图表，C 能复算实验。

## 里程碑

### M0：仓库和数据契约

- 建好 GitHub 私有仓库并邀请三人。
- 确认数据字段、目录、分支和 PR 规则。
- 完成一个可运行的最小行情抓取。

### M1：真实数据打通

- A 完成多源行情和 DeepSeek 工具调用。
- B 完成首版数据审计和字段字典。
- C 用固定数据跑通基线和留出期流程。

### M2：研究闭环

- A 固定完整数据快照。
- B 完成 EDA、图表和第一版 PPT。
- C 完成模型对比、组合和风险报告。

### M3：联调与答辩

- 三人共同检查页面、数据、模型和报告的一致性。
- B 主导两轮汇报彩排和问答演练。
- A 准备数据获取与智能体问题，C 准备建模、组合和风控问题。

## 答辩分工建议

- A：数据为什么可信，智能体如何调用工具，如何避免接口失败和幻觉。
- B：数据如何清洗，为什么这样筛选，偏差和缺失在哪里，图表说明了什么。
- C：模型为什么这样选，如何防止泄漏，样本外结果是否支持策略，成本和风险如何进入组合。
